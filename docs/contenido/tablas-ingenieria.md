# Tablas – Introducción a la Ingeniería de Software

## Tabla 5. Plantilla de lecciones – Ingeniería de software

**Lessons**  

**Topic:** Introducción a la ingeniería de software, desarrollo de software profesional, ética y estudios de caso.

**Source of information:** Libro de ingeniería de software (capítulo de introducción), artículos sobre ética profesional (ACM/IEEE), materiales de cursos universitarios.

| Level | Subtopic | Description of content | Format |
|---|---|---|---|
| 1 | Introducción a la ingeniería de software | Definición de ingeniería de software como disciplina de ingeniería que se ocupa de todos los aspectos del desarrollo de sistemas de software, diferenciándola de la programación ad-hoc. Se presentan objetivos de la asignatura y atributos de un software de calidad. | Texto, audio (clase magistral breve con ejemplos de proyectos reales). |
| 2 | Desarrollo de software profesional | Descripción de procesos de desarrollo (especificación, diseño, implementación, validación, mantenimiento) y su importancia en el contexto profesional: trabajo en equipo, uso de herramientas, estándares y documentación. | Imagen (diagrama del ciclo de vida) y explicación guiada. |
| 3 | Ética en la ingeniería de software | Presentación del código de ética y práctica profesional (ACM/IEEE), principios básicos: interés público, calidad del producto, integridad del juicio profesional, competencia, confidencialidad. | Video/presentación con dilemas éticos y preguntas de reflexión. |
| 4 | Estudios de caso | Introducción a uno o dos casos reales o verosímiles (p. ej. sistema médico crítico, sistema de gestión de datos sensibles) donde se vinculan decisiones técnicas con implicaciones éticas y sociales. | Animación o narración de casos con actividades de discusión guiada. |

## Tabla 6. Plantilla de ejemplos – Ingeniería de software

**Examples**  

**Level of complexity:** Fundamental, intermediate, advanced.

| Example number | Statement or description about the problematic situation for the example | Description of the solution |
|---|---|---|
| 1 (Fundamental) | Un equipo desarrolla una aplicación interna sin seguir proceso: no documenta requisitos, no usa control de versiones, prueba de forma informal y no mantiene registros de cambios. El sistema comienza a fallar y resulta difícil corregir errores sin introducir nuevos. | Se propone aplicar un proceso básico de ingeniería de software: identificación y documentación de requisitos, diseño modular, uso de control de versiones, pruebas sistemáticas y registro de incidencias. Se explica cómo estas prácticas transforman el trabajo en desarrollo de software profesional. |
| 2 (Intermediate) | Un desarrollador detecta un fallo grave en un módulo que gestiona datos personales; la dirección le sugiere no informar al cliente para evitar retrasos y penalizaciones económicas. | El caso se analiza usando el código de ética ACM/IEEE: prioridad al interés público y protección de datos, obligación de informar riesgos significativos y buscar soluciones responsables, aun bajo presión comercial. Se discuten posibles cursos de acción alineados con los principios éticos. |
| 3 (Advanced) | Una empresa diseña un sistema de monitoreo de actividad de empleados con registro detallado de acciones. El equipo técnico duda sobre si el alcance del sistema respeta la privacidad y la legislación vigente. | Se plantea una solución que incluye revisión de requisitos con partes interesadas, consulta legal y ética, reducción de captura de datos a lo estrictamente necesario y definición de políticas transparentes. Se vinculan las decisiones al concepto de responsabilidad profesional y diseño responsable de software. |

## Tabla 7. Plantilla de ejercicios – Ingeniería de software

**Exercises**  

**Level of complexity:** Fundamental, intermediate, advanced.

| Number | Statement or description of the exercise | Correct answer(s) of the exercise | Representation of the exercise |
|---|---|---|---|
| 1 | Crossword: completar un crucigrama con conceptos clave de la unidad ("ingeniería de software", "especificación", "validación", "mantenimiento", "proceso"). | Definiciones correctas extraídas de la introducción de ingeniería de software: ingeniería de software como disciplina de ingeniería; especificación como descripción de qué debe hacer el sistema; validación como comprobación de que el sistema cumple requisitos; mantenimiento como actualización posterior a la entrega; proceso como conjunto estructurado de actividades. | Crossword (Fundamental): crucigrama en papel o digital que refuerza vocabulario básico de la asignatura. |
| 2 | Complete: texto breve sobre el ciclo de vida del software con espacios en blanco donde el estudiante debe insertar los nombres de las actividades principales (especificación, diseño, implementación, pruebas, mantenimiento). | El texto final presenta la secuencia razonable del ciclo de vida e indica que estas actividades pueden solaparse o iterarse según el modelo de proceso, reforzando la idea de desarrollo profesional frente a improvisado. | Complete (Fundamental/Intermediate): ejercicio de completar frases que puede integrarse en materiales de clase o plataforma de aprendizaje. |
| 3 | Order: ordenar tarjetas con pasos de un proceso de desarrollo sencillo para un caso de estudio (por ejemplo, aplicación de control de tareas académicas). | Orden correcto típico: 1) comprender el problema y recopilar requisitos; 2) diseñar la solución; 3) implementar el código; 4) probar funciones clave; 5) desplegar y realizar mantenimiento. Se discute que en la práctica real hay iteraciones entre pasos. | Order (Intermediate): actividad de arrastrar y soltar que ayuda a visualizar el proceso de desarrollo de software profesional. |
| 4 | Filling words: relacionar enunciados de situaciones éticas con principios del código de ética (por ejemplo, informar un riesgo grave, proteger datos sensibles, rechazar tareas sin competencia adecuada). | Cada enunciado se completa con el principio ético adecuado: interés público, calidad del producto, competencia profesional, confidencialidad, etc. Se valida que el estudiante vincule correctamente situación y principio. | Filling words (Intermediate/Advanced): plantilla de frases donde se escriben los principios correspondientes, útil para evaluación formativa de ética. |
| 5 | Associate words: asociar distintos estudios de caso (sistema médico crítico, sistema de monitoreo de empleados, sistema financiero) con conceptos de ingeniería de software (seguridad, confiabilidad, privacidad, integridad de datos, responsabilidad profesional). | Asociaciones correctas establecen qué atributos de calidad y qué principios éticos son más relevantes en cada caso; por ejemplo, seguridad y confiabilidad para sistemas médicos, privacidad para monitoreo de empleados, integridad de datos para sistemas financieros. | Associate words (Advanced): actividad tipo mapa conceptual que vincula casos y conceptos, fomentando el pensamiento crítico sobre las implicaciones del desarrollo de software profesional. |
